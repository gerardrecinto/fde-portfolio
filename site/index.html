Joltrin

Helps teams that give an AI agent real access to a database or a cluster. It refuses a risky step, like dropping a production database, until the steps before it are recorded, and it tells the agent what to run first.

I'm a maintainer. The verification barrier side is mine: the MCP and A2A servers, the runbook loader, the Kubernetes admission gate, observe mode and the install path. The storage engine underneath was written by another maintainer.

go run github.com/sharedcode/joltrin/v5/examples/verify_barrier@latest

meshdoctor

Helps platform teams that review Istio YAML. It finds the mistakes that turn into 503s, such as route weights that do not add up to 100 or a subset nobody defined, before the change is applied. It runs in CI or in a browser tab.

Solo project. Go linter with a WebAssembly build, a Jenkins gate, runbooks for the 503 cases and a kind-based end to end test.

git clone https://github.com/gerardrecinto/meshdoctor && cd meshdoctor
go run ./cmd/meshdoctor testdata/bad.yaml

One customer visit, start to finish

The demo takes a made-up team that wants an AI agent kept away from production drops. It covers scoping, wiring their step names into a runbook, a dry run on their traces, a deploy, a restart that breaks a run, and recovery. It runs the real Joltrin server from a pinned commit and checks its own results.

git clone https://github.com/gerardrecinto/fde-portfolio && cd fde-portfolio
bash demo/run.sh

Needs Go and Python 3. The first run builds the server and takes about a minute (24 seconds on a GitHub runner, 76 on my laptop). After that it takes seconds. See the output and how to verify it.

What is real and what is simulated

Real The code, the commits and pull requests I link, the test and CI results, and everything the demo's server prints.

Simulated The example team and its agent traces in the demo. I invented them to show a visit. They are not a customer and not data from any system.

Not claimed: I have no paying customer for either project and no usage numbers to show. Joltrin is young. meshdoctor has not run against a customer's cluster.
